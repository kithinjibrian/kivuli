# kivuli — kickoff brief

*kivuli* (Swahili: "shadow") — the view is a shadow of the model.

A declarative UI framework for [Lugha](https://github.com/kithinjibrian/lugha), built on the Elm architecture and rendered to real GTK 4 widgets through [lugha-gtk](https://github.com/kithinjibrian/lugha-gtk). This brief is everything a new session needs to start: the decisions already made (do not re-litigate them), what Lugha and lugha-gtk give us, the internals, the risks, and the order of work.

Written 2026-10-16 from a design discussion in the lugha repository's sessions (after milestone 90).

---

## 1. What a kivuli app looks like

```
import kivuli.ui { View, Cmd, column, row, text, button, input };

struct Model { count: i64, name: string }

enum Msg { Add, Reset, Named(string) }

fun update(m: Model, msg: Msg): Model = match msg {
    Add => Model { count: m.count + 1, ..m },
    Reset => Model { count: 0, ..m },
    Named(n) => Model { name: n, ..m },
};

fun view(m: Model): View<Msg> = column([
    text("Hello, {m.name}").size(20),
    input(m.name, Msg.Named).placeholder("Your name"),
    text("Clicked {m.count} times"),
    row([
        button("Add", Msg.Add).style(Primary),
        button("Reset", Msg.Reset).disabled(m.count == 0),
    ]).spacing(8),
]).padding(24).window("Counter", 360, 240);

fun main(): i32 = ui.sandbox("org.lugha.counter", Model { count: 0, name: "" }, update, view);
```

The app never touches a widget. A click produces a `Msg`; `update` makes the next `Model`; `view` describes the next screen; kivuli diffs the description against the previous one and patches only what changed.

`..m` (struct update) and `Msg.Named` as a function value are **not in Lugha yet** — see §4.

## 2. Decisions (final — agreed in discussion)

1. **Two entry points**, like Elm's `Browser.sandbox` / `Browser.element`:
   - `ui.sandbox(id, init: Model, update: fun(Model, Msg): Model, view: fun(Model): View<Msg>): i32` — pure; most apps.
   - `ui.application(App { id, init: (Model, Cmd<Msg>), update: fun(Model, Msg): (Model, Cmd<Msg>), view, subscriptions: fun(Model): Sub<Msg> }): i32` — with effects.
2. **One window per app in v1**, configured from `view` with a root modifier `.window(title, width, height)`, so the title may depend on state. Multiple windows and dialogs: later.
3. **Widgets in v1:** `text(s)`, `button(label, msg)`, `input(value, on_change: fun(string): Msg)` (+ `.placeholder(s)`, `.on_submit(msg)`), `checkbox(label, checked, on_toggle: fun(bool): Msg)`, `column(children)`, `row(children)`, `spacer()`, `scroll(child)`, `separator()`, `keyed_column(children: (string, View<Msg>)[])`. v2: text area, dropdown, slider, image, table.
4. **Modifiers are methods on `View`**, chained; one that doesn't apply to a node is ignored. Layout: `padding(n)`, `spacing(n)`, `expand()`, `align(Start | Center | End)`, `width(n)`, `height(n)`. Text: `size(n)`, `bold()`, `dim()`. Button: `style(Normal | Primary | Danger | Subtle)`, `disabled(bool)`. Root: `window(title, w, h)`.
5. **Disabled = no message.** Internally a button's `on_click` is `Option<Msg>`; `.disabled(true)` sets it to `None`, which greys the widget out.
6. **Effects as data, minimal in v1:** `Cmd.none()`, `Cmd.batch(cmds)`, `Cmd.after(ms, msg)` (one-off timer), `Cmd.quit()`; `Sub.none()`, `Sub.every(ms, fun(i64): Msg)` (time in ms). File, process and network I/O are *not* commands in v1: `update` may call `std.fs` / `std.process` directly (blocking is acceptable for now).
7. **Composition by mapping**, Elm-style: `View<A>.map(f: fun(A): B): View<B>`, same on `Cmd` and `Sub`. **No framework-owned local state in v1**; add only if a real widget needs it.
8. **Performance tools in v1:** `lazy(…)` (skip building and diffing an unchanged subtree — see risk R1 for its exact shape) and `keyed_column` for reordering lists. No virtualised list in v1.
9. **`ui.testing` in v1:** inspect a `View` tree with no GTK and no display — `testing.find_button(v, "Reset").is_disabled()`, `testing.click(v, "Add") == Some(Msg.Add)`, `testing.type_into(v, placeholder, "text")` returning the message. `update` and `view` are pure, so apps test with `lughac test`.
10. **Packaging:** its own repository `kivuli` (GitHub `kithinjibrian/kivuli`, created and pushed only on the user's go), package name `kivuli`, main module `ui` (`import kivuli.ui;`), depends on `gtk` (lugha-gtk) as a git package. Rendering and diffing are private; apps see `ui` (types, widget functions, `sandbox`, `application`) and `ui.testing`. License GPL-3.0-only, like Lugha.
11. **Two small Lugha compiler milestones come first** (in the lugha repo, each with its own PRP there): struct update syntax and variants as function values (§4). No trailing-closure syntax.
12. **Order:** compiler: struct update → compiler: variants as functions → kivuli v1 → examples (counter, to-do list, stopwatch).

The user's earlier general preference: Elm over React/Flutter/Solid — chosen for value semantics, exhaustive `match` on `Msg`, pure testable `update`/`view`. No more framework comparisons.

## 3. What the platform gives us

### Lugha (v16, milestones up to 90) — things kivuli relies on

- **Generics** (functions, structs, enums), **interfaces** (structural, with the one implicit conversion: a value to an interface where one is expected — arrays of an interface type convert element by element), **enums** with payloads and exhaustive `match`, **closures** (values `{ code, env }`), **tuples**, **`Ref<T>`** (the only shared mutable box: `Ref.new`, `get`, `set`, `update`, `is`), **`@test`** + `lughac test`.
- **Value semantics:** everything copies (arrays copy-on-write); only `Ref` is shared. A closure may not reassign a captured variable (E0511) — but may `set`/`update` a captured `Ref`.
- **C interop:** `extern type` handles, callbacks with `data`/`release` (closures pinned while C holds them), `extern "symbol" fun` (several Lugha declarations of one C function), strings from C (`string` / `Option<string>` results, copied, U+FFFD), `extern struct` by value, `[link]` with `pkg-config`.
- **Gotchas met while writing lugha-gtk:**
  - `of` is a keyword (don't name a function `of`).
  - A method may not share a name with a field (E0310) — lugha-gtk names fields `ptr`, methods `handle()`.
  - A parameter may not share an imported module's name (E0311) — no `fun f(app: …)` in a file that imports `app`.
  - An interface's *default* methods are callable only through an interface value or a bound, not on the concrete type.
  - Field visibility defaults to the package, so modules of one package can read each other's fields.
  - Recursive enums through arrays are fine (`Column(View<Msg>[])`); function values can be enum payloads; functions have no `==` (so a `View` holding closures isn't `Eq`).
- **Commands:** `lughac check|build|run|test file.la`, `lughac fmt`, `lughac explain CODE`, `lughac spec` (the full language reference). Install lughac from the lugha repo with `cargo install --path .` (needs milestones 87–90; and 91–92 once built).

### lugha-gtk 0.1.0 (`gtk = { git = "https://github.com/kithinjibrian/lugha-gtk", version = "0.1" }`)

- `gtk.raw`: `public extern type GtkApplication`, `GtkWidget`, `Argv`; externs for application, window, box, button, label, entry/editable, margins; `connect_app` / `connect_widget` (renamed `g_signal_connect_data` for handlers taking their object); links GTK through `[link] pkg-config = ["gtk4"]`.
- `gtk.app.run(id, on_activate)`, `gtk.widgets` (`Widget` interface, `Window`, `Box`, `Button`, `Label`, `Entry`).
- kivuli should use **`gtk.raw`** (it manages widgets itself) and add what's missing as its own private externs (or contribute them to lugha-gtk 0.2): `gtk_box_remove`, `gtk_box_insert_child_after` / `gtk_box_reorder_child_after` (keyed lists), `gtk_widget_set_sensitive`, `gtk_widget_add_css_class` / `remove_css_class` (button styles: `suggested-action`, `destructive-action`, `flat`; text: CSS for size/bold/dim, or `GtkLabel` attributes), `gtk_widget_set_hexpand`/`vexpand`, `gtk_widget_set_halign`/`valign`, `gtk_widget_set_size_request`, `gtk_check_button_new_with_label` / `get_active` / `set_active` / `"toggled"`, `gtk_scrolled_window_new` / `set_child`, `gtk_separator_new`, `gtk_entry_set_placeholder_text` / `"activate"`, `g_timeout_add_full` (callback with `data` + `release`) / `g_source_remove`, `g_application_quit`, `gtk_window_set_title` / `set_default_size`. Check each against `/usr/include/gtk-4.0` (GTK 4.22 is installed with `libgtk-4-dev` and `pkgconf`).

## 4. The two compiler prerequisites (lugha repo, milestones 91–92)

Each needs its own discovery and PRP in the lugha repository, following that repo's `CLAUDE.md` (sessions in `CONTEXT.md`, PRP before code, test-first, merge via PR once local `fmt`/`clippy`/`cargo test` pass).

- **Struct update syntax:** `S { f: e, ..base }` — fields given explicitly, the rest copied from `base` (an expression of the same struct type, evaluated once, after the explicit fields? — decide in discovery; Rust evaluates explicit fields first, then `base`). Generic structs, nested, tuples (no), `..base` only last, E-code for a different type.
- **Variants as function values:** `Msg.Named` (a variant with payloads) used as a value is `fun(string): Msg`; `Some` as `fun(T): Option<T>` maybe; a payload-less variant stays a value. Spec currently lists what can't be a value (E0406); check what it says about variants first.

kivuli v1 can be *started* without them (writing every field, `fun(s) = Msg.Named(s)`), but the examples and README should use them, so build them first.

## 5. Internals (the design to implement)

### The view tree

```
public enum View<Msg> {
    Text(TextNode),
    Button(ButtonNode<Msg>),
    Input(InputNode<Msg>),
    Checkbox(CheckboxNode<Msg>),
    Column(Children<Msg>), Row(Children<Msg>), Keyed(KeyedChildren<Msg>),
    Scroll(…), Spacer(Layout), Separator(Layout),
    Lazy(…),            // see R1
    Window(…),          // root only
}
```
Each node carries a `Layout` (padding, expand, align, size) and its own style. Widget functions build nodes with defaults; modifiers return changed copies (`match self { Button(b) => …, _ => self }`).

### The runtime

```
struct Runtime<Model, Msg> {
    model: Model,
    tree: View<Msg>,          // the last view
    live: Live,               // the real widgets, mirroring `tree`
    update: …, view: …,       // the app's functions
}
```
Held in a `Ref<Runtime<…>>` captured by every GTK handler; `dispatch(msg)` = update → view → diff(old tree, new tree, live) → patch → store.

### The handler trick (no reconnecting signals)

Messages can't be compared (they may hold closures), so handlers never get reconnected. Each live widget is connected **once** when created; its handler reads the message to send from a `Ref<Option<Msg>>` stored with the live widget (for `input`/`checkbox`, a `Ref<fun(string): Msg>`). A patch only `set`s that `Ref`. A `None` means disabled → `gtk_widget_set_sensitive(false)`.

### Diff and patch

- Same kind at the same position → patch fields that differ (label text, sensitivity, CSS classes, layout) and re-point the handler `Ref`.
- Different kind → destroy the old widget, create the new one, insert at that position.
- Children: by position (`column`/`row`); `keyed_column`: by key — reuse, move (`gtk_box_reorder_child_after`), insert, remove.
- `input`: never overwrite the entry's text if it already equals the model's (keeps the cursor); guard the `changed` handler against echoes from programmatic `set_text`.

### Effects

- `Cmd.after(ms, msg)` → `g_timeout_add_full(ms, callback returning 0 (G_SOURCE_REMOVE), data, release)` → dispatch.
- `Sub.every(ms, f)` → after each `update`, compare the new subscriptions with the running ones (by a key: kind + interval) and start/stop GLib timeouts accordingly.
- `Cmd.quit()` → `g_application_quit`.

## 6. Risks and open questions to settle in the PRP

- **R1 — `lazy` and types.** `lazy(input: T, f: fun(T): View<Msg>)` must store `input` in a `View<Msg>` node to compare next time, but `View` is generic only over `Msg`. Options: (a) store a closure `fun(): bool` comparing against a captured previous value (needs the previous value captured — awkward); (b) `lazy(key: string, f: fun(): View<Msg>)` / `lazy_i64(key: i64, …)` — the app supplies a cheap key (Elm's `Html.Keyed`-like discipline); (c) an `Eq`-bounded interface value if Lugha supports `Eq` as an interface type (check `lughac spec`). Prefer the simplest that works; record it.
- **R2 — generic depth.** `Runtime<Model, Msg>`, `View<Msg>` with closures in payloads, `map` producing `View<B>` from `View<A>` (rebuilds the tree, wrapping each message function) — check the checker handles these instances well and IR size stays sane.
- **R3 — `map` on handlers.** `View<A>.map(f)` wraps `Msg` values and `fun(string): A` closures into `B`; the runtime only ever sees the top-level `Msg`. Make sure nested maps compose and the handler-`Ref` trick still holds.
- **R4 — GTK + GC.** Widgets hold Lugha closures only through pinned callbacks (milestone 88), released when GTK destroys the signal (`release`). Destroying a widget must not leave a live handler reading a freed `Ref` — it can't (GC), but check nothing pins forever per re-render (connect once per *widget*, never per render).
- **R5 — focus and selection** in `input` across re-renders (see the `input` note above).
- **R6 — missing lughac features** found while building: stop and report in the lugha repo (its SCOPE RULE); fix there with its own PRP or bug-fix PR, as was done for `m.H` handles (lugha PR #27).

## 7. Proposed repository layout

```
kivuli/
  lugha.toml          [package] name = "kivuli", version = "0.1.0", source = "src"
                      [packages] gtk = { git = "https://github.com/kithinjibrian/lugha-gtk", version = "0.1" }
                      [link] pkg-config = ["gtk4"]          # for kivuli's own extra externs
  src/ui.la           public API: View, Cmd, Sub, widget functions, modifiers, sandbox, application, map, lazy
  src/testing.la      ui.testing: find/click/type on a View tree — no GTK
  src/live.la         live widgets: create, patch, destroy (private)
  src/diff.la         tree diff → patches (private, pure — unit-testable)
  src/effects.la      Cmd/Sub execution on GLib timeouts (private)
  src/gtk_extra.la    externs lugha-gtk 0.1 lacks (private)
  examples/counter.la, examples/todo.la, examples/stopwatch.la
  test/               @test files for diff and testing (no display needed)
  README.md, LICENSE (GPL-3.0 text: /usr/share/common-licenses/GPL-3)
```
Note: `testing` as a module name inside `kivuli` gives `import kivuli.testing;` — decision 9 says `ui.testing`; either make `testing` a module re-exported from `ui` (`public import testing;` in `ui.la` → `ui.testing.click(…)`) or name it `kivuli.testing`. Decide in the PRP.

## 8. Process for the new session

1. **Start in the lugha repo** for milestones 91–92 (§4): discovery → PRP → approval → build, per its `CLAUDE.md`. Reinstall `lughac` afterwards.
2. **Then the kivuli repo** (`/home/kithinji/Documents/kithinji/kivuli`): set up a `CLAUDE.md` adapted from lugha's essentials that apply to a Lugha package (sessions log, PRP before code, test-first with `@test`, one PRP at a time, no file over 500 lines, ask before outward-facing actions), then **PRP-001: kivuli v1** from this brief.
3. **Build kivuli v1 in steps**, each ending in something that runs:
   1. static render: `sandbox`, `text`/`button`/`column`/`row`, full rebuild on every message (no diff yet);
   2. diff + patch + the handler-`Ref` trick;
   3. `input`, `checkbox`, `keyed_column`, `scroll`, `spacer`, `separator`;
   4. modifiers and styles;
   5. `application` with `Cmd`/`Sub`;
   6. `lazy` (R1);
   7. `ui.testing`;
   8. examples (counter, to-do, stopwatch) and README.
4. **Verify** with `lughac check`/`build` on every example, `lughac test` on the diff and testing modules (no display), and a windowless smoke run like lugha-gtk's `test/smoke.la`. Opening the windows is the user's.
5. **Publishing** (`gh repo create kithinjibrian/kivuli --public`, push `main`, tag `v0.1.0`) only on the user's go.

The user's working preferences carried over: attach a recommended answer to every discovery question; lead design advice with the plain answer and a code example; when asked to "build all", build approved PRPs in order and merge each once local checks pass without stopping between them.
